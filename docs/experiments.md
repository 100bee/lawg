# 실험 결과 (dev)

7단계 실험 기록입니다. 기준값(검색 방식, 거절 임계값, 프롬프트)은 모두 **dev만 보고** 정했고, test 99문항은 아직 열지 않았습니다. test 측정은 평가셋을 확정한 뒤 한 번만 합니다.

**조건:** dev 99문항(라벨 v2: 답변 대상 64, 거절 35) · 근거 자료 148개(조문 78, 판례 35, 양형기준 7, 해설 25, 신고·상담처 3) · 분류·작성 `gemini-3.5-flash-lite` · 임베딩 `gemini-embedding-001` · 2026-11-12

평가셋은 초안입니다. 질문과 정답 조문은 Claude가 썼고 소유자 검토 전입니다(`[확인]` 표시 14건).

## 요약

| 실험 | 비교 | 결과 (dev) |
| --- | --- | --- |
| 1 쟁점 변환 | 사연만 vs 사연 + 쟁점 표현 | 근거 재현율 0.792 → **0.932** |
| 2 검색 방식 | Keyword / Hybrid / Vector | 0.016 / 0.932 / **0.951**, 조문 번호 사연 1위 2 / 8 / **10** (10개 중) |
| 거절 기준 | 임계값 0.56~0.66 | **0.58 유지**. "근거 없음"은 임계값으로 가를 수 없음 |
| 3 근거 자료 유무 | 모델 기억만 vs RAG | 법정형이 현행과 맞음 74% vs **100%**, 사기죄 현행 형 0/18 vs 전부 |
| 4 질문 쌍 | 피해자 쪽 vs 가해자 쪽 | 조문 하나 이상 공유 13/13, 조문이 완전히 같음 6/13 |

리포트를 끝까지 만드는 dev 전체 측정은 벡터 검색으로 다시 돌리던 중에 무료 임베딩 한도(하루 약 1,000회)가 끝났습니다. 그래서 99건 중 77건까지만 끝났습니다. 내일 한도가 풀리면 남은 22건을 마저 돌려 이 문서를 갱신합니다.

## 실험 1: 쟁점 변환

분류 단계가 붙이는 법률 쟁점 표현("먹튀" → "거래 사기")을 검색어에 넣을 때와 뺄 때를 비교했습니다. 숫자는 정답 조문 중 근거 관문(벡터 0.58)을 통과해 리포트 작성에 넘어간 비율입니다.

| 검색어 | 후보 재현율 | 근거 재현율 | 조문이 하나도 안 남은 사연 |
| --- | ---: | ---: | ---: |
| 사연 그대로 | 0.854 | 0.792 | 2 / 64 |
| 사연 + 쟁점 표현 | 0.948 | **0.932** | 0 / 64 |

*하이브리드 검색 기준이며, 실험 2의 다른 방식에서도 같은 방향입니다.*

차이가 난 11건 중 6건이 거래 사기였습니다. "입금 확인되자마자 차단 박고 잠수탔어요"처럼 "사기"라는 말이 없는 사연은 사연만으로는 형법 제347조가 근거 관문을 넘지 못했습니다.

## 실험 2: 검색 방식

| 방식 | 근거 재현율 (dev 64건) | 조문 번호 사연 10개: 조문 자리 8개 안 | 1위 |
| --- | ---: | ---: | ---: |
| Keyword | 0.016 | 3 | 2 |
| Hybrid (벡터 0.72 + 키워드 0.28) | 0.932 | 10 | 8 |
| **Vector** | **0.951** | **10** | **10** |

- **키워드 검색은 거의 쓸모가 없었어요.** PostgreSQL `simple` 사전은 한국어 조사를 떼지 못합니다. 그래서 "모욕했다가"가 조문의 "모욕한"과 맞지 않고, "311조"도 "제311조"와 맞지 않아요. 조문 본문에는 법령 이름도 없어요.
- **하이브리드는 벡터보다 낮았어요.** 「형법」을 인용하는 형사소송법·소송촉진법 조문이 "형법"이라는 낱말 하나로 키워드 점수를 받았어요. 그래서 "형법 311조로 고소당했어요"에서 1위가 형사소송법 제245조의7이 됐어요.
- 그래서 리포트 검색의 기본값을 **vector**로 바꿨습니다(`REPORT_RETRIEVAL_MODE`). 차이는 dev 64건 중 1~2건이라 test에서 다시 확인합니다.
- 조문 번호 사연은 "형법 311조로 고소당했어요", "정통망법 74조 위반이라는데", "성폭법 제13조 통매음으로" 같은 10개예요(`app/experiments.py`의 `ARTICLE_STORIES`).

벡터 검색에서도 놓친 조문은 4건이었어요.

| 사연 | 놓친 조문 | 이유 |
| --- | --- | --- |
| 단톡 저격 욕설, "사과하고 합의하면 끝나나요" | 형법 제312조 (고소) | 친고죄 조문은 사연과 말이 닮지 않음 |
| 가짜 이벤트 페이지로 받은 아이디로 접속 | 정보통신망법 제48조, 제49조의2 | 피싱 쪽 조문이 사기 조문에 밀림 |
| "인스타 계정 털렷는데" | 정보통신망법 제48조 | 오타, 계정 탈취만 적힘 |
| 내 사진으로 사칭 계정 | 스토킹처벌법 제2조 | 사칭이 스토킹 정의에 들어간다는 연결이 사연에 없음 |

## 거절 기준 (근거 관문 임계값)

검색 결과 중 조문이 하나라도 임계값을 넘어야 리포트를 씁니다. 답변 대상 64건과, 범위 안이지만 맞는 조문이 없는 "근거 없음" 3건으로 임계값을 바꿔 보았습니다(벡터 검색).

| 임계값 | 근거 재현율 | 잘못 거절 (답변 대상 64) | 잘못 통과 (근거 없음 3) |
| ---: | ---: | ---: | ---: |
| 0.56 | 0.966 | 0 | 3 |
| **0.58** | 0.951 | **0** | 3 |
| 0.60 | 0.935 | 2 | 3 |
| 0.62 | 0.901 | 2 | 1 |
| 0.64 | 0.794 | 7 | 1 |
| 0.66 | 0.576 | 15 | 0 |

임계값으로는 "근거 없음"을 가를 수 없었습니다. 셋을 모두 막으려면 0.66까지 올려야 하고, 그러면 답변 대상 15건이 거절됩니다. 그래서 **0.58을 유지**하고, "근거 없음"은 작성 단계(모델의 `answerable=false`)와 분류에 맡깁니다. "근거 없음"이 3건뿐이라 이 결론은 약합니다.

## 실험 3: 근거 자료 유무 (RAG를 쓸 때와 안 쓸 때)

같은 모델에게 근거 자료 없이 "이 사연과 관련될 수 있는 처벌 조문을 최대 5개 고르고, 법정형을 적어라"라고 시켰습니다. 그 결과를 RAG 리포트와 비교했습니다. 조문은 국가법령정보센터의 현행 원문과 대조했습니다.

| | RAG 없음 | RAG (Lawg) |
| --- | ---: | ---: |
| 정답 조문을 고른 비율 (조문만) | 0.854 (64건) | 0.939 (벡터, 41건) · 0.923 (하이브리드, 61건) |
| 없는 조문을 지어냄 | 0 / 165 | 0 (근거 자료 밖 번호는 검증에서 거절) |
| 법정형 숫자가 현행 조문과 맞음 | **96 / 129 (74%)** | **78 / 78 (100%)**, 인용한 출처와 대조 |
| 형법 제347조(사기)를 현행 형(20년 이하 징역, 5천만원 이하 벌금)으로 적음 | **0 / 18** | 모두 |

- **모델은 조문 번호는 잘 기억했지만 법정형은 옛날 것이었습니다.** 사기죄를 언급한 18건 모두 "10년 이하의 징역 또는 2천만원 이하의 벌금"이라고 적었습니다. 개정 전 형입니다. 정보통신망법 제70조(명예훼손)도 15건 중 10건이 현행과 달랐습니다.
- **지어낸 조문은 없었습니다.** 근거 자료 148개 밖에서 고른 조문 21개(10종: 형법 제309조, 제329조, 정보통신망법 제44조의7 등)도 모두 실제로 있었습니다. 다만 고른 조문이 사연에 맞는지는 따로 보지 않았습니다.
- 법정형 대조에서 13개는 뺐습니다. 금지 조문(정보통신망법 제48조, 제49조, 게임산업법 제32조)에 법정형을 붙인 것이라 그 조문 본문에는 숫자가 없습니다.
- RAG 쪽의 100%는 "처벌 범위 문장의 숫자가 그 문장이 인용한 출처 본문에 있다"는 뜻입니다. 숫자는 모두 근거 자료에서 옮겨 왔으므로 현행 원문과 같습니다.
- 숫자 대조는 문장에서 "N년", "N월", 금액만 뽑아 비교하는 단순한 방식입니다(`penalty_numbers`). 단위를 다르게 쓴 맞는 답(예: "2백만원")은 틀린 것으로 셀 수 있습니다.

## 실험 4: 피해자·가해자 질문 쌍

같은 사건을 피해자 쪽과 가해자 쪽에서 적은 질문 13쌍이 같은 조문을 인용하는지 봤습니다. 이 숫자는 하이브리드 검색으로 dev를 끝까지 돌린 결과(라벨 v1)입니다. 벡터 검색으로 다시 돌리는 중에 무료 임베딩 한도가 끝나 9쌍까지만 끝났습니다(괄호 안).

| 기준 | 13쌍 중 |
| --- | ---: |
| 인용한 조문·판례가 완전히 같음 | 4 (0.308) |
| 판례를 빼고 조문만 같음 | 6 (0.462) · (벡터 9쌍 중 5) |
| 조문을 하나 이상 함께 인용 | **13 (1.0)** · (벡터 9쌍 중 8) |

- 13쌍 모두 조문을 하나 이상 함께 인용했습니다. 판례는 사연의 표현에 따라 달라졌습니다.
- 조문이 달랐던 7쌍 중 5쌍은 한쪽이 조문을 하나 더 붙인 경우였습니다.
  - 가해자 쪽: 스토킹처벌법 제18조, 정보통신망법 제74조 같은 처벌 조문
  - 피해자 쪽: 성폭력처벌법 제13조, 정보통신망법 제74조
  - 사기 쌍의 가해자 쪽에는 형법 제286조(협박죄의 미수범)가 붙었습니다. 사기와 맞지 않는 인용이라, 미수 조문은 각 죄의 장에 따로 있다는 점을 작성 지시에 넣을지 검토가 필요합니다.
- 핵심 조문이 갈린 것은 2쌍입니다.
  - 단톡방 저격 글: 피해자 쪽은 모욕(형법 제311조), 가해자 쪽은 명예훼손(형법 제307조)으로 읽었습니다. 사연에 사실 적시가 있었는지 애매한 경우입니다.
  - 피싱 페이지로 계정 탈취: 피해자 쪽은 정보통신망 침입(제48조, 제49조의2), 가해자 쪽은 사기(형법 제347조)를 골랐습니다. 둘 다 컴퓨터등사용사기(제347조의2)는 함께 인용했습니다.

## 재현 방법

평가셋은 확정한 뒤 `backend/data/eval/`에 넣습니다. 지금은 초안이라 저장소에 없습니다.

```bash
# 검색 실험(실험 1·2, 임계값, 조문 번호 사연): 모델 호출 없이 임베딩만 씀
docker compose run --rm backend python -m app.experiments --dataset data/eval/dev.jsonl --split dev --cache data/eval-cache.json
# 리포트 끝까지 평가: 모델 호출은 디스크 캐시에 저장돼 다시 돌리면 0회
docker compose run --rm backend python -m app.evaluate_reports --dataset data/eval/dev.jsonl --split dev --cache data/eval-cache.json
```
