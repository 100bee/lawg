# Retrieval 평가 방법

실제 의미 임베딩 비교 결과는 [Gemini 소규모 실험](retrieval-experiment-v2-gemini-budget.md)에 기록한다. 사용 모델은 `gemini-embedding-001`, 저장 차원은 1536이다.

## 데이터

문서 12개와 평가 질문 20개를 사용한다. 답변 가능한 질문 15개, 거절 대상 5개이며 `dev` 14개·`challenge` 6개로 나눴다. 정답 문서, 답변 가능 여부, 사람이 확인할 핵심 답변 항목을 함께 기록했다.

## 지표

- **Recall@5:** 상위 5개 청크에서 정답 문서를 찾은 비율을 질문별로 계산한 뒤 평균한다. 복수 정답 문서 중 하나만 찾으면 그 비율만 반영한다.
- **MRR:** 검색 결과의 문서명 중복을 제거한 뒤 첫 정답 문서 순위의 역수를 평균한다.
- **검색 근거 판정 일치율:** 답변 허용/거절이 정답 라벨과 같은 질문의 비율이다. 전체 생성 답변의 사실 정확도가 아니다.
- **잘못된 허용:** 거절 대상 중 답변 가능으로 판정한 비율이다.
- **잘못된 거절:** 답변 가능한 질문 중 거절한 비율이다.

Recall과 MRR은 답변 가능한 15문항에서 계산하고, 전체 판정 일치율은 20문항에서 계산한다. 빈 분모의 비율은 JSON에서 null로 표시한다.

## 해석 원칙

답변 모델은 호출하지 않는다. 같은 검색 근거 판정 함수를 채팅과 평가에서 사용하지만, 생성 모델이 추가로 거절하는지는 별도 검증이 필요하다. 임베딩 재사용 옵션에서는 준비 시간을 검색시간과 분리한다. 데이터·모델·판정 기준·checksum을 원본 결과와 함께 기록하고, 결과에 맞춰 검증 질문이나 기준을 사후 변경하지 않는다.
