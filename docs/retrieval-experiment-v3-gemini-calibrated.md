# Gemini 거절 기준 보정 실험

실행일: 2026-11-10 16:12 KST (`2026-11-10T07:12:08Z`). [원본 결과 JSON](retrieval-experiment-v3-gemini-calibrated.json). 이전 결과: [v2](retrieval-experiment-v2-gemini-budget.md).

## 문제

[v2 실험](retrieval-experiment-v2-gemini-budget.md)에서 Vector·Hybrid는 거절 대상 5문항을 **모두** 답변 가능으로 판정했다. 원인은 기준값이었다. `gemini-embedding-001`의 코사인 유사도는 문서와 무관한 질문(프린터, 휴가 규정)에서도 약 0.54가 나와, 의미 유사도 기준 0.35는 사실상 모든 질문을 통과시켰다.

## 기준을 정한 방법

dev 질문 14개의 Vector Top-1 유사도만 보고 기준을 정했다. challenge 질문의 점수는 기준을 정하는 데 사용하지 않았다.

| dev 그룹 | Top-1 유사도 범위 |
| --- | ---: |
| 답변 가능 12문항 | 0.693 ~ 0.833 |
| 거절 대상 2문항 | 0.542 ~ 0.548 |

두 그룹 사이 구간의 중간값 **0.62**를 Gemini 전용 기준(`GEMINI_MINIMUM_SEMANTIC_SCORE`)으로 정했다. OpenAI 임베딩은 점수 분포가 달라 기존 0.35를 그대로 유지했다. OpenAI 기준은 실제 데이터로 검증하지 않았다.

## 결과

v2와 같은 데이터셋·문서(checksum 동일), 같은 조건(질문 임베딩 배치 1회, 방식별 1회 실행)으로 실행했다. 문서 재색인과 생성 모델 호출은 없었다.

| 방식 | Recall@5 | MRR | 근거 판정 일치율 | 거절 대상 거절 성공 | 답변 가능 질문의 잘못된 거절 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Vector | 100.0% | 1.000 | 75.0% → **90.0%** | 0/5 → **3/5** | 0/15 |
| Keyword | 93.3% | 0.817 | 80.0% | 4/5 | 3/15 |
| Hybrid | 100.0% | 0.878 | 75.0% → **90.0%** | 0/5 → **3/5** | 0/15 |

- dev: 거절 대상 2/2 거절, 답변 가능 질문 잘못된 거절 0/12.
- challenge: 거절 대상 1/3 거절, 답변 가능 질문 잘못된 거절 0/3.
- Keyword는 의미 유사도를 쓰지 않으므로 결과가 바뀌지 않았다. 검색 순위(Recall·MRR)도 바뀌지 않았다.

## 남은 실패와 답변 단계 확인

검색 단계에서 여전히 통과한 2문항은 운영 문서와 같은 어휘를 쓰지만 문서에 없는 사실을 묻는다.

- `challenge-04`: 429 오류 당시 고객사별 실제 피해 금액과 보상 승인자
- `challenge-05`: pgvector 관리자의 생일과 개인 전화번호

유사도는 각각 0.715, 0.684로 답변 가능 질문과 같은 범위에 있다. **임베딩 유사도만으로는 "주제는 같지만 답이 없는 질문"을 구분할 수 없다.** 이 경우는 답변 단계가 막아야 한다.

두 질문을 Hybrid 모드로 실제 `/api/chat`에 보냈다. 두 건 모두 Gemini(`gemini-3.5-flash-lite`)가 호출되었고(입력 893·485토큰), 모델이 `answerable=false`로 거절해 `grounded=false`가 기록되었다. 따라서 거절 대상 5문항은 검색 단계에서 3개, 답변 단계에서 2개가 거절되었다.

## 한계

- 기준은 dev 거절 대상 2문항으로 정했다. 경계를 정하기에 매우 적은 수다.
- challenge 질문은 v2 보고서에서 이미 공개적으로 분석했다. 기준을 정할 때 사용하지는 않았지만 완전한 미공개 시험 세트는 아니다.
- 답변 단계 확인은 2건뿐이다. 답변 가능한 질문을 생성 모델이 잘못 거절하는지는 이번에 측정하지 않았다.
- 다음 단계는 처음 보는 거절 대상 질문을 추가해 기준을 다시 확인하는 것이다.

## 재현

```bash
docker compose exec -T backend python -m app.evaluate --repetitions 1 --reuse-query-embeddings > docs/my-gemini-retrieval.json
```

`grounding_policy.version`이 `coverage-v2-gemini-calibrated`인지 확인한다. 전체 테스트 **25개 통과**(Gemini 기준 단위 테스트 2개 추가).
