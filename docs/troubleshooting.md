## 검색

### 1. 자료를 늘리자 조문이 검색에서 사라짐

- **증상:** 자료를 19개에서 148개(판례 35, 해설 25 등)로 늘리자 정답 조문이 근거 5개 안에 드는 비율이 0.93에서 0.19로 떨어졌습니다. 답변할 문항 63건 중 38건은 근거에 조문이 하나도 없었습니다.
- **원인:** 모든 자료를 한 순위로 섞어 찾았습니다. 판례와 해설은 평소 말투에 가까워서 "돈 보냈는데 잠수탔어요" 같은 사연과 더 비슷하게 잡히고, 짧고 딱딱한 조문은 밀려났습니다.
- **해결:** 종류별로 따로 찾고 자리를 나눴습니다(조문 8 · 판례 2 · 양형기준 1 · 해설 3). 질문 임베딩은 한 번만 만들어 모든 종류에 씁니다(`SOURCE_QUOTAS`, `report.search`).
- **확인:** 재현율이 0.905로 돌아왔습니다. 사건 유형 필터도 시험했지만 조문·해설에는 효과가 없어서 양형기준에만 씁니다.

### 2. 신고처 안내(ECRM)가 리포트에서 빠짐

- **증상:** 경찰청 사이버범죄 신고시스템(ECRM)을 인용한 리포트가 18건에서 2건으로 줄었습니다.
- **원인:** 신고처 안내는 "안내" 종류로 해설과 같은 3자리를 놓고 경쟁했는데, 사연과 더 비슷한 해설에 밀렸습니다.
- **해결:** 신고·상담처(ECRM, 132, 1366)를 `contact` 종류로 분리했습니다. 순위가 아니라 사건 유형으로 붙이고, 이미 유형으로 골랐으므로 근거 관문도 거치지 않게 했습니다.
- **확인:** ECRM 인용이 41건으로 늘었습니다.

### 3. 키워드·하이브리드 검색이 한국어 사연에 약함

- **증상:** 키워드 검색만 쓰면 정답 조문 재현율이 0.016이었습니다. 하이브리드(벡터 0.72 + 키워드 0.28)는 벡터 검색만 쓸 때보다 낮았습니다(0.932 대 0.951). "형법 311조로 고소당했어요"에서 1위가 형사소송법 제245조의7이었습니다.
- **원인:** PostgreSQL `simple` 사전은 한국어 조사를 떼지 못합니다. "모욕했다가"는 "모욕한"과 맞지 않고, "311조"는 "제311조"와 맞지 않습니다. 조문 본문에는 법령 이름도 없습니다. 맞는 낱말은 "형법" 정도였는데, 「형법」을 인용하는 절차 조문이 그 점수를 받았습니다.
- **해결:** 리포트 검색 기본값을 벡터로 바꿨습니다(`REPORT_RETRIEVAL_MODE=vector`). 키워드와 하이브리드는 실험용으로 남겼습니다.
- **확인:** 조문 번호가 든 사연 10개 중 벡터는 10개, 하이브리드는 8개, 키워드는 2개를 1위로 찾았습니다.

### 4. 유사도 임계값으로 "근거 없음"을 가를 수 없음

- **증상:** 처음 쓰던 기준 0.35에서는 범위 밖 질문도 모두 통과했습니다. 0.62로 올리자 계정 해킹 사연이 0.612로 거절됐습니다.
- **원인:** Gemini 임베딩의 코사인 유사도는 관련 없는 질문에도 0.55 근처가 나옵니다. 게임·온라인 사연이면 어떤 조문과도 0.6 이상이 나옵니다.
- **해결:** 0.58로 정했습니다. 답변할 문항 64건이 모두 조문을 남기는 가장 높은 값입니다. "범위 안이지만 맞는 조문이 없는" 사연은 작성 단계에서 모델이 `answerable=false`로 거절하게 했습니다.
- **확인:** "근거 없음" 3건을 모두 막으려면 0.66까지 올려야 하는데, 그러면 답변할 문항 15건이 거절됩니다. **아직 못 고친 문제**입니다. dev에서 "근거 없음" 거절은 0/3이었습니다.

## 작성·검증

### 5. 해설을 조문 칸에 인용하면 리포트 전체가 거절됨

- **증상:** 자료를 늘린 뒤 dev 측정을 시작하자 멀쩡한 사연이 "근거 없음"으로 거절됐습니다.
- **원인:** 검증 규칙은 "관련 조문" 칸에 조문과 판례만 허용했습니다. 생활법령 해설은 조문을 풀어 쓴 글이라, 모델이 해설을 조문 칸에 넣었고 그 하나로 리포트 전체가 거절됐습니다.
- **해결:** 해설이나 양형기준을 인용한 항목만 빼고 나머지는 남깁니다. 남은 조문·판례가 없을 때만 거절합니다.
- **확인:** 측정을 중단하고 고친 뒤 다시 돌려, 답변할 문항을 모두 리포트로 처리했습니다.

### 6. 출처 칸에 "S9, S10"을 쓰면 리포트 전체가 거절됨

- **증상:** 검색이 제대로 된 사연 2건(패드립 모욕, 신고처 문의)이 "근거 없음"으로 거절됐습니다.
- **원인:** 모델이 출처 번호 두 개를 한 칸에 `"S9, S10"`, `"S1, S15"`처럼 써서, "없는 번호 인용"으로 걸렸습니다. 결론이 반대인 판례 두 건을 한 항목에서 비교하라는 지시가 이런 형식을 부른 것으로 보입니다.
- **해결:** 출처 칸에서 S 번호를 모두 뽑아 읽습니다. "관련 조문" 칸은 첫 번째 조문·판례 번호만 남깁니다.
- **확인:** 저장된 두 초안을 새 규칙으로 다시 검사해 둘 다 리포트가 되는 것을 확인했습니다. 테스트를 추가했습니다.

### 7. 검증 규칙과 작성 지시가 서로 충돌

- **증상:** 첫 dev 측정에서 답변할 문항 중 82.5%만 리포트가 됐습니다.
- **원인:** 작성 지시는 "실제 형은 재판에서 정해진다는 점을 덧붙인다"였고, 검증 규칙은 "처벌 범위 문장은 모두 출처가 있어야 한다"였습니다. 모델이 지시를 따른 문장이 검증에서 걸렸습니다. 스키마에 안 맞는 JSON이 가끔 오는 것도 한 원인이었습니다.
- **해결:** 숫자가 없는 처벌 범위 문장은 출처 없이 허용했습니다. 형식이 틀린 응답은 한 번 다시 요청합니다.
- **확인:** 둘째 측정에서 96.8%가 됐습니다.

## 분류

### 8. 주어가 생략된 가해자 문장을 피해자로 읽음

- **증상:** 모델 사전 시험에서 입장 판정이 18/20이었습니다. 틀린 2건은 모두 "아이템 판다고 하고 돈만 받고 차단했어요"처럼 주어가 없는 가해자 문장이었습니다.
- **원인:** 한국어는 주어를 자주 생략합니다. 모델은 사기 사연을 피해 신고로 읽는 경향이 있었습니다.
- **해결:** 분류 지시에 "주어가 생략된 문장은 동사의 주체로 판단한다"는 규칙과 대비되는 예문 두 개를 넣었습니다. 화면에서도 입장을 확인하고 바꿀 수 있게 했습니다.
- **확인:** 같은 문장이 가해자로 판정됐습니다. dev 입장 정확도는 0.98입니다.

## 자료

### 9. 모델이 기억하는 법정형이 옛날 것

- **증상:** 근거 자료 없이 모델에게 법정형을 물으면 사기죄 18건이 모두 "10년 이하의 징역 또는 2천만원 이하의 벌금"이라고 답했습니다. 이는 개정 전 형입니다.
- **원인:** 형법 제347조는 2025년 12월 개정돼 법정형이 20년 이하 징역, 5천만원 이하 벌금으로 올랐습니다. 모델의 학습 데이터에는 옛 조문만 있습니다. 처음 만든 화면 예시도 옛 숫자를 쓰고 있었습니다.
- **해결:** 조문 원문을 국가법령정보센터에서 시행일과 함께 그대로 받아 씁니다. 화면의 조문 원문은 모델이 쓴 글이 아니라 색인된 문서입니다. 처벌 범위 문장의 숫자는 인용한 출처 본문에 있어야 합니다.
- **확인:** RAG 리포트는 처벌 범위 숫자 78개가 모두 출처와 맞았습니다. RAG 없이는 74%만 맞았습니다(실험 3).

### 10. 게임 거래 사기에 계좌 지급정지를 안내할 위험

- **증상:** 사기 피해자에게 "은행에 지급정지와 피해금 환급을 신청하라"고 쓸 수 있었습니다. 흔히 알려진 대응이라 모델이 자연스럽게 씁니다.
- **원인:** 통신사기피해환급법은 재화 거래를 가장한 사기를 대상에서 뺍니다(제2조 단서). 게임머니·아이템·중고 거래 사기는 대부분 해당하지 않습니다.
- **해결:** 작성 지시에서 이 안내를 금지했습니다. 연락처·기관명·숫자는 근거 자료에 있는 것만 쓰게 했습니다.
- **확인:** 법 원문과 대조했습니다. 저장된 dev 리포트 초안 174건에서 "지급정지"·"환급"이 나온 것은 0건입니다.

## 수집

### 11. 판례 페이지 머리말을 못 읽고, 전원합의체는 반대의견까지 수집됨

- **증상:** 판례 35건 중 3건이 "unexpected page header"로 실패했습니다. 성공한 전원합의체 판례(2020도5813)는 8,754자였습니다.
- **원인:** 머리말 정규식이 "선고 2020도5813 판결"만 가정했습니다. 그래서 "전원합의체 판결"이나 "판결 : 항소"는 읽지 못했습니다. 전원합의체 판결요지에는 반대의견과 보충의견이 같이 실려 있습니다.
- **해결:** 정규식이 두 형식을 받게 했습니다. 판결요지에서 "[대법관 … 반대의견]" 단락을 다음 쟁점 번호 전까지 빼는 `majority_only`를 넣었습니다(자체 검사 포함).
- **확인:** 35건이 모두 수집됐고, 2020도5813은 4,266자가 됐습니다.

### 12. 한글 파일 이름

- **증상:** 판례 파일 이름이 `precedent-2022도10688.md`처럼 한글을 포함했습니다.
- **원인:** macOS(NFD)와 Linux(NFC)는 한글 파일 이름을 다르게 저장합니다. 그래서 같은 파일이 저장소와 컨테이너에서 다른 경로가 될 수 있습니다.
- **해결:** 사건 번호의 한글을 정해진 로마자로 바꿉니다(`2022도10688` → `2022do10688`). 표에 없는 글자가 나오면 수집을 멈춥니다.

## 색인

### 13. 지운 자료가 DB에 남아 계속 인용될 수 있음

- **증상:** 검토에서 뺀 조문 파일을 지워도 배포된 DB에는 남아 있었습니다.
- **원인:** 다시 색인할 때 폴더에 있는 파일만 추가·갱신하고 지우지는 않았습니다.
- **해결:** 다시 색인한 뒤 폴더에 없는 근거 자료 문서를 지웁니다. 처음에는 이름만 바꾼 파일까지 지워져 통합 테스트가 깨졌습니다. 그래서 내용이 같아 기존 문서와 연결된 것과, 이번에 색인에 실패한 파일 이름은 남기게 했습니다.
- **확인:** 통합 테스트로 확인합니다. 파일이 없는 조문은 지워지고, 업로드한 문서는 남습니다.

### 14. 색인 실패가 조용히 묻힘

- **증상:** 색인 결과에 `failed: 1`만 나오고 어느 파일이 왜 실패했는지 알 수 없었습니다.
- **원인:** 색인 함수가 예외를 잡아 개수만 셌습니다.
- **해결:** 실패한 파일 이름과 예외를 로그로 남깁니다. 다시 돌리니 성공해서, 임베딩 API의 일시적 오류로 보입니다.

## 모델·한도

### 15. Gemini 과부하(503)와 한도(429)

- **증상:** 사전 시험에서 40건 중 4건이 503이었습니다. 과부하 시간대에는 9건 중 6건이 실패하거나, 1건에 17초가 걸렸습니다.
- **원인:** 무료 등급은 과부하 시간대에 응답을 거절하고, 분당·일일 한도가 있습니다.
- **해결:**
  - 생성: 한 번 다시 시도하고, 그래도 안 되면 `gemini-3.1-flash-lite`로 한 번 바꿉니다.
  - 임베딩: 다시 시도만 합니다. 다른 모델의 벡터를 섞으면 안 되기 때문입니다.
  - 화면: 과부하, 분당 한도, 일일 한도를 각각 다른 문구로 보여 줍니다(503). 일일 한도는 응답 본문의 `PerDay`로 구분합니다.
  - 진행 표시: 10초가 넘으면 안내를 띄우고, 90초가 넘으면 중단합니다.
- **주의:** 실험을 돌릴 때는 대체 모델을 꺼야 합니다(`GEMINI_FALLBACK_CHAT_MODEL=`). 그러지 않으면 결과에 두 모델이 섞입니다.

### 16. 평가 중 임베딩 하루 한도가 끝남

- **증상:** 벡터 검색으로 dev 전체를 다시 돌리다 99건 중 77건에서 멈췄습니다. 이어서 라벨만 바꿔 다시 채점하려 해도 65건이 실패했습니다.
- **원인:** 모델 호출 결과는 디스크에 저장했지만, 질문 임베딩은 매번 새로 만들었습니다. 그래서 같은 질문을 검색 실험 여러 번과 평가 여러 번에 걸쳐 수백 번 임베딩했고, 하루 약 1,000회 한도를 다 썼습니다.
- **해결:** 평가와 실험이 질문 임베딩도 저장하게 했습니다(`cached_embeddings`). 키는 임베딩 모델, 차원, 작업 종류, 문장입니다. 이제 라벨이나 검증 규칙을 바꿔 다시 채점해도 API를 부르지 않습니다.
- **배포 참고:** 리포트 1건은 생성 2회와 임베딩 1회를 씁니다. 서비스에서는 생성 한도가 먼저 끝날 것으로 봅니다.

## 개발 환경

### 17. 테스트가 실제 Gemini를 부름

- **증상:** 로컬에서 `pytest`를 돌리면 임베딩 테스트 하나가 `ProviderBusy`(일일 한도)로 실패했습니다.
- **원인:** `.env`에 Gemini 키와 `AI_PROVIDER=gemini`가 있어서, 테스트가 실제 API를 불렀습니다.
- **해결:** CI처럼 키 없는 로컬 모드 설정을 겹쳐서 돌립니다.

```bash
docker compose -f docker-compose.yml -f compose.local.yaml run --rm \
  -e TEST_DATABASE_URL=postgresql+psycopg://ragops:ragops@db:5432/lawg_test backend python -m pytest -q
```

통합 테스트는 트랜잭션 안에서 돌고 되돌리지만, 색인된 개발 DB와 섞이지 않게 별도 DB(`lawg_test`)를 씁니다.
